# Tag catalog

Empirical groundwork for tag normalization/categorization decisions (see
[docs/adr/0004](../adr/0004-omit-translation-credit-tags-from-tokenization.md) and
[docs/adr/0005](../adr/0005-normalize-compilation-cart-in-1-phrasing.md)): the raw,
deduplicated `(...)`/`[...]` tag vocabulary actually in use across the whole library —
every ROM and every piece of box art, every system, not just one console at a time.

This directory holds **data, not decisions**. It's regenerated by running the app with
a CLI flag (`Services/TagExtractor.cs`, wired up in `Program.cs`), not written by hand,
and deliberately does no normalization or categorization of its own — that's follow-on
work, once there's a real vocabulary to look at instead of the handful of examples
that happened to turn up during ADR-0003's validation.

## Files

- **`raw-tags.txt`** — every unique tag-group string seen (the inner text of one
  `(...)` or `[...]` group), one per line, sorted. Case-sensitive, undeduplicated
  across spelling variants on purpose — e.g. `Ja` and `Japan` both appear as separate
  lines even though they mean the same thing. That variance is itself part of what
  this catalog exists to surface, not noise to fold away before you get to look at it.
- **`raw-tags-counts.tsv`** — the same tags with occurrence counts and a heuristic
  `category` column (`Services/TagCategorizer.cs`): `tag`, `category`, `total`, `roms`
  (how many ROM filenames it appeared in), `images` (how many image filenames). Sorted
  by total count descending, so the "obvious" bucket (region/revision/language words)
  naturally floats to the top and the long tail of one-off, weird, or hack/translation/
  compilation-specific tags sinks to the bottom.

  `category` is one of the following, listed in **rank order** — how much a
  difference in a tag of that category tends to mean "different box art," most
  decisive first (decided 2026-09-23; the order is `TagCategorizer.TagCategory`'s
  declaration order): `Disc` (a wrong disc is a wrong file outright), `Region`,
  `Unofficial` (unlicensed/altered distribution — Unl, Pirate, Aftermarket,
  Reproduction, Repro — a different product, not a variant of the licensed one),
  `Preview` (pre-release/promotional, not the final retail build — Beta, Demo,
  Proto/Prototype, Sample, Promo, Kiosk demo units — a different build),
  `Revision` (Rev/version numbers, plus "Alt" — a No-Intro/Redump "alternate dump
  of the same release" disambiguator, not a legitimacy flag, so it lives here
  rather than in `Unofficial` — the same box nearly every time), `Platform`
  (hardware, storefronts, distribution services, mini-console/arcade reissues —
  Virtual Console, Switch Online, Steam, GameCube, Arcade, ...), `Label`
  (publisher/reissue brand names — Zeppelin Games, Limited Run Games, ...),
  `Language` (mostly already carried by `Region`), `Date`, `TranslationCredit`
  and `HackOrPatchCredit` (never get their own art — a patch is scored against
  the original's box). The same order also groups into four **significance**
  levels (`TagCategorizer.TagSignificance`, each a contiguous run of the rank):
  *Decisive* (Disc, Region), *Distinguishing* (Unofficial, Preview, Revision),
  *Descriptive* (Platform, Label, Language, Date), *Irrelevant* (TranslationCredit,
  HackOrPatchCredit); a **combined label** for a compound tag where every
  comma/dash-separated clause resolved to a *known* category, just not all the
  same one — joined with `+` in rank order (most significant first) rather than
  one opaque "Compound" bucket, e.g. `"NA, Rev 2"` → `Region+Revision`,
  `"NA - Disc 3"` → `Disc+Region`; or `NeedsReview` (at least one clause didn't
  match anything above — the actual "a human should look at this" pile, outside
  the ranking). It's a **labeling pass, not a decision** — it doesn't change
  matching/scoring behavior and isn't itself the normalization/categorization
  call ADR-0004/0005 still need to make; it just says where to spend attention.
  Non-exhaustive by design (same spirit as `RegionCatalog`/`TagWordCatalog`) —
  expect it to misclassify or under-classify things the real vocabulary hasn't
  been checked against yet.

  On the real library (2026-09-17 scan): `Region`/`Preview`/`Unofficial`/`Language`/
  `Revision`/`Disc`/`Platform`/`Label`/combined labels together already cover ~90% of total
  *occurrences* despite `NeedsReview` alone being ~58% of *unique* tags — the long
  tail is wide but mostly low-frequency, so skimming `NeedsReview` sorted by count is
  enough to find what's actually worth designing a rule for (e.g. `Taiwan`/`Russia`
  turned up there as real `RegionCatalog` gaps, not just noise).
- **`categories/`** — `raw-tags-counts.tsv` split into one file per category
  (`Region.tsv`, `Language.tsv`, `NeedsReview.tsv`, ...), each sorted by count
  descending, so a single bucket can be skimmed on its own instead of grepping the
  combined file. Rebuilt from scratch on every run (stale files from a category that
  no longer exists don't linger).
- **`scan-info.txt`** — provenance for the current `raw-tags.txt`/`raw-tags-counts.tsv`:
  when they were generated and from which ROMs/Images root paths, plus file counts.
  This is a snapshot of one specific library at one point in time, not a permanent,
  complete-for-all-time vocabulary — adding a new system or art pack will introduce
  tags this scan has never seen, so re-run the extraction after a meaningful library
  change rather than trusting a stale copy. **Gitignored, not committed** — it embeds
  this machine's absolute ROMs/Images root paths (e.g. `/mnt/roms/mister/games/`),
  which is local filesystem layout, not vocabulary data; `raw-tags.txt`/
  `raw-tags-counts.tsv` contain no paths at all (only bracket-tag content pulled from
  filenames), so those two are the actual shareable, committed artifacts.

## Regenerating

```
dotnet run -- --extract-tags
```

Defaults to the ROMs/Images root paths already saved in the app's own settings
(`~/.config/GameArtMatch/settings.json` — the same `RomsRootPath`/`ImagesRootPath`
used to browse for a system's folder in the GUI), so no arguments are needed for the
common case. Override either root, or the output directory, if needed:

```
dotnet run -- --extract-tags --roms-root /path/to/roms --images-root /path/to/art --out docs/catalog
```

## Intended next steps (not yet done)

1. Skim `raw-tags-counts.tsv` from the top down. The high-count entries are almost all
   already-handled region/revision/language words (`Japan`, `USA`, `Rev 1`, `Unl`,
   `Beta`, `Proto`, ...) — confirms `RegionCatalog`/`TagWordCatalog` already cover the
   bulk of real traffic.
2. Focus analysis on the long tail: multi-word phrases (translation credits, hack/patch
   descriptions, compilation cart game lists), inconsistent phrasing variants (the
   "N-in-1" family), and anything that doesn't obviously belong to a known category.
3. Feed what's found back into ADR-0004 (translation-credit / hack-jargon omission)
   and ADR-0005 (compilation-cart phrasing) to turn this raw list into an actual
   decision, rather than designing either rule from a handful of hand-picked examples.
